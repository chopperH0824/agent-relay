# Agent Relay v0.2.0

This minor release delivers the v0.2 roadmap items: a previewable schema migration, opt-in lifecycle hooks that change no harness configuration, and cross-worktree coordination that each worktree enables for itself. Existing projects keep working read-only until their owner approves a migration.

## Highlights

- **Previewable migration.** Schema `1` (v0.1.x) state stays readable by `report`, `status`, and `doctor`, which now mark `migration_required`. Writes require `migrate --yes`. The migration backs up `config.json` and `HANDOFF.md`, rewrites only the schema markers in `config.json` and `goals.json`, logs the migration, and leaves goals, tasks, events, sealed versions, and environments untouched.
- **Opt-in lifecycle hooks.** A runner or wrapper can pipe a bounded JSON object into `hook before-write|checkpoint|task-finish`, or read the report on `session-start|session-end`. Hooks are off by default, accept only documented fields, reject input above 64 KiB, and never write harness configuration.
- **Cross-worktree coordination.** `worktree enable` registers a worktree in a registry stored in the repository's common Git directory, so cleanup of a worktree cannot discard another worktree's leases. Overlapping write scopes across worktrees are rejected, claims must stay consistent, and `doctor` verifies them.
- **Stronger locks.** Locks record an owner identity, are removed only by the owner, and are reclaimed only when the recorded process is gone.


GitHub CLI 2.90.0+ preview, pinned to this release:

```bash
gh skill install chopperH0824/agent-relay agent-relay@v0.2.0 --scope user
```

Updating the Skill does not automatically upgrade existing projects. For a selected project, ask the agent to update it while preserving adapter scope and history. It runs `init --dry-run` (or `migrate --dry-run`) first and applies the approved plan with `--yes`. Unknown local runtime edits still require review; there is no force-replace switch.

## Upgrading a project from v0.1.x

1. `python3 .agent-relay/relay.py migrate --dry-run` shows the schema change, the preserved record families, and the backup directory. It writes nothing.
2. `python3 .agent-relay/relay.py migrate --yes` applies it once; repeat runs report `changed: false`.
3. `python3 .agent-relay/relay.py doctor` should report a healthy schema `2` state.

If a v0.1.x runtime is installed in the project, run the new installer's `init` so the project runtime is replaced before migrating; see the changelog for the ownership rules.

## Optional features

```bash
python3 .agent-relay/relay.py hooks enable --dry-run
python3 .agent-relay/relay.py hooks enable --yes
echo '{"title":"Fix login","scopes":["src/**"]}' | python3 .agent-relay/relay.py hook before-write

python3 .agent-relay/relay.py worktree enable --dry-run   # run once per participating worktree
python3 .agent-relay/relay.py worktree enable --yes
python3 .agent-relay/relay.py worktree status
```

## Compatibility and boundaries

- Python 3.9+ and standard-library only.
- Report schema remains `v1`; new fields (`state_schema_version`, `migration_required`, `hooks_enabled`, `coordination`) are additive and documented in the bundled schema.
- Cross-worktree coordination covers same-machine worktrees of one repository that share a common Git directory. It does not extend locking to other machines, network filesystems, or cloud-sync folders, and a worktree that never opts in keeps its own local state.
- Hooks do not install harness configuration, background processes, or global settings.
- Relay health still describes record integrity and freshness, not acceptance, approval, or deployment.
