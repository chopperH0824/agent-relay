Agent RelayPersistent project handoff protocol
一次安装，项目长期生效

Skill 只负责安装，
项目自己持续交接。

第一次执行后，Agent Relay 把自动入口、运行脚本和交接状态留在当前项目。后续任何 Agent 打开文件夹都会先接手上下文，并可随时生成状态快报，无需用户再次触发 Skill。

自动进入Harness 启动时读取项目入口
自动沉淀完成任务后刷新交接与历史
跨 Agent同一份状态，不维护多套真相
01 / SIMPLIFIED SCOPE

只保留五项能力

用户只需要感知五件事：新 Agent 能接上、过程有记录、现状能秒报、成果能封版、多人不会撞车。其余实现细节都隐藏在项目运行时中。

01

自动接手

任何 Agent 开始前先读短交接，知道目标、进度、阻塞和下一步。

02

自动记录

任务结束后记录问题、动作、结果和验证，不保存冗长聊天与思维过程。

03

快速汇报

只读汇总健康、目标、任务、版本、环境、阻塞与下一步。

04

自动封版

明确要定版或交付时保存不可变副本，后续继续修改工作稿。

05

自动协调

Agent 先认领任务和文件；环境不兼容时说明替代方案并请求确认。

02 / ONE-TIME INSTALL

第一次执行发生什么

安装 Skill 是一次性的引导动作。真正让能力长期存在的是留在项目里的自动入口、轻量运行脚本和状态目录。

STEP 1执行安装 Skill
→
STEP 2识别项目根目录
→
STEP 3写入 Harness 入口
→
STEP 4安装项目运行时与状态
→
STEP 5doctor 验证并结束
之后不再依赖主动触发：Codex、Pi、Claude Code、Cursor、Gemini 等通过各自的项目级入口自动读取同一份交接协议。
03 / ONE SOURCE OF TRUTH

入口很多，状态只有一份

AGENTS.md 作为通用主入口；Claude、Gemini 和 Cursor 的适配文件只负责转接，不分别复制目标、任务和历史。

项目入口

AUTO LOAD

告诉不同 Harness：开始前读取交接、修改前认领任务、结束时更新状态。

交接总览

HANDOFF

保持短小，只显示当前目标、进行中任务、最近动作、风险和下一步。

项目运行时

RELAY CLI

以原子方式完成任务认领、事件落盘、环境比较、封版和总览刷新。

历史仓库

IMMUTABLE

按事件和版本保存事实记录，避免多个 Agent 同时追加一个大文件。

后续每次自动循环

用户照常描述任务。Agent Relay 在后台完成接手与收尾，除非发现文件冲突、环境缺失或定版范围不明确，才需要打断用户确认。

2. 认领范围声明任务与计划修改文件，检查是否冲突
↓
3. 执行验证根据用户当前问题完成工作并进行必要验证
←
4. 更新交接记录结果、释放任务、识别目标与封版意图
↑

任何 Agent 第一时间读取的短总览

最近动作问题、处理、结果和验证
当前版本最近封版和后续工作稿状态

05 / QUICK REPORT

一句话，汇报现在的情况

relay report 只读取规范状态，不翻完整历史、不认领任务、不改写交接。Agent 可以直接转述固定结构的结果。

01
快只读状态目录并做轻量一致性检查，设计目标为数秒内返回。
02
准HANDOFF 落后、租约过期或能力缺失时明确标记 degraded / stale。
03
可复用Markdown 给用户，JSON 给 Hook、MCP、脚本和其他 Agent。
04
无副作用不刷新租约、不创建事件、不改变任何项目状态。

06 / VERSION SEALING

定版只做一次判断

识别的是“现在要交付”的完整语义，不是机械扫描单个关键词。明确时自动执行，模糊时只确认范围。

收到用户消息

例如“定版”“就按这个发”“可以了”。

→
是否明确立即交付？

明确则继续；无法判断是步骤完成还是整体定版时询问。

→
生成不可变版本

复制交付物、计算校验值、汇总版本历程，再继续维护工作副本。

自动封版：“最终版”“就按这个发”“现在发给领导”。
先确认：单独的“可以了”“就这样”，且上下文无法确定范围。
07 / MULTI-AGENT SAFETY

并行可以，撞文件不行

每个 Agent 开始前声明写入范围。不同文件可以并行；同一文件必须等待、拆分任务，或使用独立 Git worktree。

文件范围认领

Agent Asrc/api/**
Agent Bdocs/**
若 Agent C 也要修改 src/api/**，系统先阻止写入并给出等待或 worktree 方案。
任务关系文件关系处理
不同任务不重叠允许并行
不同任务写入重叠阻止第二个写入者
同一任务可拆分拆成子任务后分别认领
同一模块必须同时修改使用独立 worktree 后合并
原 Agent 失联租约已过期记录接管原因后允许接管
08 / MINIMAL PROJECT FOOTPRINT

项目里只留下必要内容

共享事实与本机环境分开。可提交的记录经过脱敏；锁、缓存、私有路径和机器状态默认不进入 Git。

01
目标只提醒当前用户消息始终优先，不以历史目标阻止任务。
02
环境按变化记录事件只引用快照 ID，避免重复保存整台电脑信息。
03
不记录秘密禁止 Token、密码、Cookie、私钥和完整环境变量值。
04
不编造历史跨 Harness 聊天不可访问时留空，从安装后开始沉淀。
05
安装可逆幂等、可预览、可卸载，不覆盖现有项目说明。
